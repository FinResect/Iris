# DDR3

Ti60F225 DDR3 subsystem used by Iris.

- Memory: MT41J128M16, 16-bit DDR3, DDR3-800
- AXI data width: 128 bits, address 28 bits, `BURST_LEN` 127 (2 KB per burst)
- Fabric / AXI clock: 100 MHz (`core_clk`)
- DDR PHY clocks: `ddr_tdqss_clk` / `ddr_tac_clk` / `ddr_twd_clk` at 400 MHz
- Controller core clock: 200 MHz (`ddr_core_clk`)

## Layout

| Path | What |
|---|---|
| `efx_ddr3/efx_ddr3_axi.sv` | Efinix `efx_ddr3_axi` IP 5.17 (encrypted, generated by `efx_ipmgr` 2026.1). Single shared address channel `axi_a*` + `axi_atype`. |
| `efx_ddr3/ddr3_controller.vh` | Generated geometry/timing defines (`DRAM_WIDTH 16`, `ROW 14`, `COL 10`, `BANK 3`, `BL 8`, `WFIFO_WIDTH 128`). |
| `efx_ddr3/ddr3_controller.bin` | Microcode ROM loaded by the controller's scheduler. |
| `axi_atype_bridge.v` | 2:1 read-priority address mux from the frame buffer's separate AW/AR onto the controller's shared `axi_a*`. Pure combinational, 0 FF / 1 LUT. |
| `fb/` | Triple-bank DDR3 frame buffer (`frame_buffer` / `ddr_buffer` / `ddr_wr_buffer` / `ddr_rd_buffer` / `data_tx` / ...). |
| `ddr3_gray_frame_buffer.v` | Legacy 240x135 grayscale DDR3 frame buffer (not instantiated in `top.v`). |

## AXI note

`efx_ddr3_axi` exposes one address channel (`axi_aid/aaddr/alen/asize/aburst/alock/avalid/aready`
+ `axi_atype`), not separate AW/AR. Its internals, however, contain independent AW/AR FSMs
and address queues plus outstanding-transaction counters — visible in `outflow/iris_ws.map.v`
as `r_aw_state` / `r_ar_state`, `u_wr_addr_fifo` / `u_rd_addr_fifo`, `r_wr_b_count[8:0]`,
`r_rlast_cnt[15:0]`. Overlapping read and write bursts are fully supported; the only hardware
limit is one address transfer per cycle on the shared bus.

`axi_atype_bridge` therefore does nothing but time-multiplex. Read is granted first whenever
it asks, because the display read path is real-time (`data_tx` holds only a half-line FIFO)
while the write path has an 8.5-line WR FIFO fed by a slow sensor. An earlier version of the
bridge serialized whole transactions (wait for B before AR, wait for RLAST before AW,
write-priority). That was a reference-host habit, not a controller requirement, and it
blocked the display read for the duration of every write burst.

See `docs/摄像头延迟与帧率优化分析.md` §4.1 for the full evidence and verification.

## Calibration

`efx_ddr3_axi` brings up the PHY and raises `cal_done` / `cal_pass`. The frame buffer is
connected to the AXI channels in `top.v`; addresses must not be issued before `cal_done`.
