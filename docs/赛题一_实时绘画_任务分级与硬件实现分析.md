## 一、赛题要求原文梳理

### 赛题背景

基于 **RISC-V + FPGA 异构平台**，设计轻量化神经网络硬件加速器；利用 FPGA 并行流水线将风格迁移网络（简化版 CycleGAN / Fast Neural Style / 轻量化 CNN）完全或部分硬件化，对实时视频流逐帧风格化。RISC-V 只负责摄像头采集配置、视频流格式转换、UI 叠加等高层控制，构建低延迟、低功耗、高帧率的边缘 AI 视频处理系统。

### 任务说明

- MIPI CSI-2 采集摄像头视频流；
- FPGA 内完成轻量化风格迁移网络推理加速，把每帧转为指定风格（梵高、浮世绘、水墨等）；
- HDMI 输出处理后的视频；
- RISC-V 实现 UI 叠加（原画 vs 风格画对比视图）。

### 基础要求（4 项）

1. **MIPI 视频流采集与预处理**
   - 用 MIPI D-PHY RX IP + CSI-2 RX Controller 接入 SC431HAI；
   - FPGA 实现 CSI-2 协议解析、RAW 转 RGB（debayer）、Resize 到目标分辨率（**最低 640×480 @ 30fps**）；
   - 双缓冲（Ping-Pong Buffer）预处理帧存入外部 DDR，确保不丢帧。

2. **轻量化风格迁移网络硬件加速器**
   - 选一个轻量化风格迁移网络（简化 CycleGAN / Fast Neural Style / 自研微型 CNN）；
   - 至少硬件化：卷积层（3×3 或 5×5）、激活函数（ReLU）、批归一化/实例归一化的硬件近似；
   - 通过 AXI4 从 DDR 读输入图像块，流水线处理后写回结果帧。

3. **HDMI 视频输出与软硬件协同**
   - 标准 HDMI 时序（**最低 720p@60fps 或 1080p@30fps**），从 DDR 读结果帧输出；
   - RISC-V C 驱动：摄像头初始化与寄存器配置、网络权重加载与部署、加速器任务调度（启动/等待/中断）；
   - 原画 vs 风格画对比显示（左原、右风格；或按键切换全屏）。

4. **基础 Demo 与性能验证**
   - 展示实时风格化效果；
   - 屏幕叠加显示 FPS，**640×480 下稳定 ≥15fps**。

### 高阶挑战（4 项）

1. **多风格实时切换**：预置 ≥2 种风格权重；通过按键/串口在**不重启、不重配 FPGA**下动态切换；切换延迟 <100ms 且不丢帧。
2. **分辨率与帧率提升**：提升到 **1280×720 @ 30fps 或更高**；流水线深度优化（层间融合、行流式处理），减少 DDR 中间结果读写；鼓励 DSP 实现脉动阵列/权重固定流。
3. **超轻量化网络自设计**：自研/剪枝 **参数量 <500KB** 的网络；提交结构图、参数量统计，并与标准网络对比 PSNR/SSIM 与推理延迟。
4. **创意交互展示**：语音控制切换、手势识别触发滤镜、风格化画面实时推流手机 APP 等；鼓励短视频展示。

### 技术提示（官方）

1. 优先用内置 MIPI D-PHY RX IP + CSI-2 RX Controller，降低外部电路复杂度。
2. 网络轻量化：U-Net 极小版、Fast Neural Style 的 1/4 通道版、二值/三值网络（BNN/TNN）。
3. 流水线关键：避免"整帧输入→整帧输出"的宏流水线，采用**行流水线（Line-based Pipeline）**。
4. 画质与速度权衡：边缘实时性比极致画质更重要。
5. 展示效果最大化：彩色图案/人脸/风景，挥手切换风格。

## 二、任务等级划分（基础 → 进阶 → 高阶）

按"可独立验收 + 逐级叠加"的原则，把赛题拆成 **6 个等级（L0~L5）**，其中 L1~L4 对应基础要求，L5 起为进阶/高阶。每个等级给出**验收标准**与**依赖关系**。

| 等级 | 名称 | 对应赛题 | 核心交付 | 验收标准 | 依赖 |
|---|---|---|---|---|---|
| **L0** | 环境与板级打通 | 前置 | Efinity 工程、点灯、HDMI 彩条、串口 | 彩条稳定显示；串口可交互 | — |
| **L1** | 视频采集与预处理 | 基础 1 | CSI-2 采集→Debayer→Resize→DDR 双缓冲 | 640×480 图像无丢帧、无错位，可稳定读到 DDR | L0 |
| **L2** | 风格迁移加速器（单层/小网络） | 基础 2 | 卷积 + ReLU + BN 硬件模块，AXI4 读写 DDR | 单帧风格化结果正确（可先跑固定测试图/离线比对） | L1 |
| **L3** | 完整网络 + HDMI 输出 + 软硬协同 | 基础 2/3 | 完整风格化流水线 + HDMI 显示 + RISC-V 调度 | 屏幕可见风格化视频；RISC-V 能启停/等待加速器 | L2 |
| **L4** | 基础 Demo 与性能达标 | 基础 4 | 对比视图 + FPS 叠加 | 640×480 稳定 **≥15fps** | L3 |
| **L5a** | 多风格动态切换 | 高阶 1 | 双份以上权重 + 切换通道 | 切换 <100ms、不丢帧、不重配 FPGA | L4 |
| **L5b** | 分辨率/帧率提升 | 高阶 2 | 720p@30 或更高；行流水线优化 | 1280×720@30 稳定；DDR 读写次数明显下降 | L4 |
| **L5c** | 超轻量网络自设计 | 高阶 3 | <500KB 自研网络 + 对比分析 | 提交结构图/参数量；PSNR/SSIM 与延迟对比 | L4 |
| **L5d** | 创意交互 | 高阶 4 | 语音/手势/推流等 | 现场可演示的互动功能 | L4 |

> **建议**：先以 L4 为"必须完成线"，确保基础分拿满，再按 L5a → L5b → L5c/L5d 顺序叠加（L5a 性价比最高，L5b 最能体现 FPGA 功力）。

## 三、硬件资源总览与预算

### 3.1 芯片资源（Ti60F225）

> 数据来源：Elitestek《Ti60 Data Sheet》DSTi60-v3.8（2026-03）。本板为 **Ti60F225I3**（工业级速度等级，核压 0.95V，温度 −40~100°C）。

| 资源 | Ti60F225 数量 | 对本题的意义 |
|---|---|---|
| Logic Elements (LE) | **62,016** | 视频流水线、总线互连、控制器 |
| XLR 单元（其中 SRL8） | 60,800（14,720） | 逻辑+布线交换单元；SRL8 可作 8-bit 移位寄存器 |
| 全局时钟/控制信号 | 最多 32（F225 经 GPIO 15 个） | 时钟树/复位/使能网络 |
| 内嵌 RAM | **2.6 Mb（256 块 × 10 Kbit，≈327 KB）** | 行缓存/窗口寄存器/权重缓存；**注意 <500KB 网络放不下** |
| DSP blocks | **160** | 卷积乘法主力（Normal 模式 **19×18** + 48bit；另有 Dual/Quad/**BFLOAT16 FMA 浮点** 模式） |
| PLL | **4**（BL/TL/TR/BR） | 像素时钟、MIPI byte clock、DDR、HDMI TMDS |
| 高速 I/O (HSIO) | **140**（单端；差分对 70） | MIPI/LVDS/HDMI 等差分 |
| 高压 I/O (HVIO) | **23** | 按键/LED/低速控制 |
| MIPI D-PHY | 1.5 Gbps（I3 等级，HSIO 软 D-PHY，支持 CSI-2/DSI） | 摄像头采集与显示发送 |
| 硬核 RISC-V | 无（使用 Sapphire 软核） | 高控制 |
| DDR | 外挂 DDR3（板载 16-bit） | 帧缓存、权重存储 |

> **注**：Ti60 全芯片 HSIO=142 / HVIO=27 是 **F256 封装**数字，本板 **F225** 为 HSIO **140**、HVIO **23**。
> **速度等级**：I3（本板）/ C3 / C4 / Q3 核压 0.95V，LVDS 半速率与 MIPI 最高 1.5Gbps、DSP/BRAM/全局时钟最高 1000MHz；C3L/C4L/I3L 低功耗档核压 0.85V、速率略降。
> **关键约束 1**：内嵌 RAM 仅 ~327KB，而高阶网络参数 <500KB，**权重无法全部常驻片上**，必须"权重流式从 DDR/Flash 读取"或量化压缩。
> **关键约束 2**：DSP 只有 160 个，直接决定卷积峰值算力（见 3.3）。

### 3.2 板级接口资源

| 接口 | 规格 | 本题用途 |
|---|---|---|
| MIPI CSI-2 输入 | FPC J4/J5（SC431HAI 4-lane） | 摄像头视频流 |
| HDMI 输出 | FPGA 高速 IO + LVDS 模拟 TMDS | 显示 |
| DDR3 | MT41J128M16JT-125，16 位，2Gb，最高 800Mbps | 帧缓存、权重 |
| GE 以太网 | YT8531SC，RGMII | 进阶：推流/上报（L5d） |
| UART | FT4232 | 调试、串口指令（L5a） |
| I2C | FPGA 3.3V IO / 板载传感器 | 摄像头配置 |
| 按键/LED | 4 键 + 8 LED | 风格切换、状态指示 |
| Flash | GD25LQ64 8MB | 固化、权重存储 |

> 板级硬件细节见同目录《SC431HAI_硬件设计指南.md》与《Ti60F225_DemoBoard_v4_用户手册.md》。**MIPI 使用前必须将 J2/J3 选为 1.2V**。

### 3.3 算力与带宽预算

**DDR3 带宽**：16 位 × 800Mbps = **12.8 Gbit/s ≈ 1.6 GB/s**（理论峰值）。

**卷积峰值算力**（DSP 160 × 200MHz × 2（乘加））：
- 约 **64 GMAC/s**（理论峰值）。
- 实际流水线效率按 20~40% 计，约 **13~26 GMAC/s** 有效。

> **频率上限**：Ti60F225I3 的 DSP/BRAM/全局时钟缓冲最高可跑 **1000MHz**（数据手册 Table 52）。此处按保守的 200MHz 估算，若时序收敛可上探到更高频率以换取算力；但实际仍受 DDR 访存与流水线效率约束。

**帧流带宽**（以 RGB888）：

| 分辨率/帧率 | 单帧字节 | 数据率（写+读各一次） |
|---|---|---|
| 640×480 @ 30fps | 0.92 MB | 2 × 27.6 = 55 MB/s |
| 1280×720 @ 30fps | 2.76 MB | 2 × 82.9 = 166 MB/s |
| 1920×1080 @ 30fps | 6.22 MB | 2 × 186.6 = 373 MB/s |

远低于 DDR3 峰值，**帧流不是瓶颈**；瓶颈在 **CNN 的中间特征图与权重访问**。因此 **"行流水线 + 层间融合"是达标的关键**（官方提示第 3 条）。

**粗算示例**：若简化风格迁移网络在 640×480 上约 **0.5~1.5 GMAC/帧**，
- 15fps → **7.5~22.5 GMAC/s**，处于 160 DSP 的有效能力范围；
- 720p@30（约 2~6 GMAC/帧）→ **60~180 GMAC/s**，**明显超出**，必须靠深度优化（降通道、量化、稀疏、BNN/TNN、行流式减少访存）或降低分辨率/帧率。

> **结论**：基础 640×480@15fps 可行；720p@30 属于"必须动架构"的高阶目标。

## 四、各任务模块的硬件资源与实现方法

### 4.1 MIPI CSI-2 采集与预处理

**硬件资源**：MIPI D-PHY RX（HSIO 差分对，4 lane）、PLL（byte clock）、HSIO 若干。

**实现方法**：

1. **采集**
   - 使用 Efinix `efx_csi2_rx` IP（本仓库 07/10 demo 已用，版本 5.6/5.9/5.15），4-lane、Continuous clock、`PIXEL_FIFO_DEPTH` 2048~4096；
   - SC431HAI 配置：1920×1080 RAW10（或按需缩小窗口寄存器 `0x3208~0x320b`），4-lane，DT `0x2b`；
   - I2C 初始化：161 项寄存器序列（参考 `i2c_master_reg_rom.v`），`I2C_DEVICE_ADDR=0x60`；
   - **可先用现有 demo 的采集通路，缩短 L1 周期**。

2. **Debayer（RAW→RGB）**
   - RAW10 解包为 8/10bit Bayer（RGGB/BGGR），2×2 单元；
   - 资源：**2~3 个行缓存（Line Buffer）** + 3×3 窗口寄存器 + 双线性插值（每像素 ~9 次乘加）；
   - 10bit×10bit 加法可用 LUT/DSP；插值系数为 1/4、1/2 等，可用**移位加法**避免乘法器。

3. **Resize（缩放到目标）**
   - 基础：**最近邻**（行/列抽取，几乎零资源，需坐标生成 + 简单行丢弃 FSM）；
   - 进阶：**双线性**（2×2 插值，需 1~2 行缓存 + 定点权重 LUT）；
   - 缩放比例建议用"整数比抽取"简化（如 3:1）以节省资源。

4. **时序/跨时钟域**
   - 采集在 MIPI pixel clock（`clk_pixel`，如 50MHz）、处理在系统时钟、写 DDR 在 AXI 时钟，需 **异步 FIFO**；
   - 行结束/帧结束作为帧同步信号送入双缓冲。

**资源估算（L1）**：

| 模块 | LE | BRAM | DSP |
|---|---|---|---|
| CSI-2 RX IP（黑盒） | 较大（IP 内部） | 有 | – |
| Debayer | ~2~4K | 2~3 行缓存 | 少量 |
| Resize（最近邻） | ~1K | 1 行缓存 | 0 |
| Ping-Pong 控制 | ~1K | 少量 | 0 |

### 4.2 DDR 双缓冲 / 帧缓存

**硬件资源**：DDR3 软核控制器（参考 07/10 demo 的 `ddr3_top`）、AXI4 互连、DDR3 引脚（Bank 3B/4A/4B，1.5V）。

**实现方法**：
- 采用 **三缓冲（Triple Buffer）** `FB_NUM=3`（现有 demo 已用），比双缓冲更能抗撕裂；
- 写通路：采集像素 → 打包（如 2~4 像素/128bit）→ AXI4 突发写（Burst 127）；
- 读通路：处理模块/DDR 读 → 解包 → 时序重建（`data_tx`）；
- 带宽优化：**burst 长度最大化**、位宽 128bit、写合并。
- **行流式替代方案**（高阶）：预处理与 CNN 在行缓冲内直接衔接，减少一次 DDR 往返。

**资源估算（L1）**：DDR 控制器 IP + AXI 互连 + 打包/解包 ≈ 3~6K LE + 少量 BRAM。

### 4.3 轻量化风格迁移网络加速器

**硬件资源**：DSP（160）、BRAM（2.6 Mb ≈ 327KB）、AXI4 主口、权重缓存。

**实现方法**：

1. **网络选择**
   - 基础：Fast Neural Style 的 1/4 通道版、微型 CNN、或 U-Net 极小版；
   - 量化：INT8/INT16（DSP 做 8×8 或 16×16 MAC）；
   - **BN 折叠进卷积权重**（推理期离线完成），避免运行时归一化；
   - **Instance Norm** 无法离线折叠，需运行时统计（均值/方差）+ 硬件近似（如用逐通道移动平均或 LUT 近似）。

2. **卷积加速器架构**
   - **行流式（Line-based）+ 权重固定**：一行像素流入，3×3/5×5 窗口滑动，权重常驻寄存器/BRAM；
   - 卷积核并行度 P（如 8/16/32 个 MAC），受 DSP 数限制（P×kernel 需 ≤160）；
   - 脉动阵列（Systolic Array）或权重固定流（Weight-Stationary）；
   - 激活 ReLU：比较/选择（近零资源）；
   - 下采样/上采样：转置卷积或插值。

3. **权重与数据流**
   - 权重：因内嵌 RAM 仅 ~327KB，网络 >327KB 时需 **从 DDR 流式读取**（预取 + 双缓冲权重缓存）；
   - 输入/输出特征图：行条带（line stripe）经 BRAM 缓冲，**避免整帧 DDR 往返**；
   - AXI4 主口负责读权重/图块、写结果。

4. **软硬接口**
   - 寄存器组（APB/AXI-Lite）：启动、层配置、权重基址、输入/输出地址、状态/中断；
   - RISC-V 负责配置寄存器、加载权重到 DDR、启动并等待中断。

**资源估算（L2/L3）**：

| 项目 | 估算 |
|---|---|
| 卷积 MAC 阵列 | 占用大部分 DSP（如 64~128 个 DSP 做并行） |
| 行缓存/窗口 | BRAM 若干（每行：宽 × 位宽） |
| 权重缓存 | BRAM 数十 KB + DDR 流式 |
| 控制/FSM/地址 | 5~15K LE |
| ReLU/BN/归一化 | 1~3K LE + 少量 DSP |

> **DSP 占用是首要瓶颈**：先确定每层并行度与目标频率，核算 160 个 DSP 是否够用，再决定网络规模。

### 4.4 HDMI 视频输出与显示

**硬件资源**：HSIO 差分对（TMDS 4 对）、PLL（像素时钟）、LVDS SERDES TX。

**实现方法**：
- **直接复用** `03_hdmi_tx_demo`（彩条→TMDS）与 `02/09` 的 `dvi_encoder`（8b→10b TMDS）；
- 硬 LVDS SERDES 10:1，`dvi_encoder` 产生 `tmds_data0/1/2` 与 `tmds_clk`；
- 像素时钟：720p60 = 74.25MHz，1080p60 = 148.5MHz，640×480@60 = 25.175MHz；
- **注意差分对 P/N 对调**、勾选 `Enable Common Mode Driver`（见硬件指南）；
- 显示侧从 DDR 结果帧读取 → 时序重建（`data_tx`）→ TMDS 输出。

**资源估算**：编码器 + 时序 + 读通路 ≈ 3~6K LE + 1 PLL + 4 对 HSIO。

### 4.5 RISC-V 软硬件协同

**硬件资源**：Efinix Sapphire SoC（efx_soc，VexRiscv），AXI4 主/从、APB、UART、GPIO、SPI、I2C、中断。

**实现方法**（参考 `08_ti60f225_soc_demo`）：
- SoC 作为控制核心：AXI4 主口接 DDR3 控制器；APB 挂自定义加速器寄存器；
- 摄像头 I2C 配置（可用 SoC I2C 或 FPGA I2C 控制器）；
- 软件：`bsp_init()` → 配置 sensor → 加载权重到 DDR → 使能加速器 → 轮询/中断等待 → 切帧；
- 中断：加速器完成中断经 `io_apbSlave` / `userInterruptA` 接入 PLIC；
- 自定义指令（可选）：把归一化/量化等算子做成 RISC-V 自定义指令（L5b/自由发挥）。

**资源估算（L3）**：Sapphire SoC ≈ 8~15K LE + BRAM + 外设。

### 4.6 UI 叠加与对比显示 / FPS 显示

**实现方法**：
- **分屏**：显示控制器根据像素坐标选择读"原图帧"或"风格帧"的 DDR 地址（左右各半，或画中画）；
- **文字/数字叠加**：字模 ROM（BRAM）+ 坐标比较；FPS 数字由帧计数器 + 秒基准生成；
- RISC-V 可通过寄存器控制 OSD 开关/文字内容（对应"UI 叠加"由 RISC-V 负责）。

**资源估算**：~2~4K LE + 小 BRAM。

### 4.7 多风格切换（进阶）

**实现方法**：
- DDR/Flash 中预置 ≥2 组权重；
- 切换 = 更新加速器的"权重基址"寄存器，并做一次流水线冲刷（避免半帧混用权重）；
- **关键**：切换发生在帧边界，且权重预取双缓冲，保证不丢帧；
- 触发：按键（消抖）或串口指令（UART 中断）；
- 延迟 <100ms：主要取决于权重切换/预取时间与帧边界等待。

**资源增量**：几乎为 0（只需额外 DDR 空间 + 控制寄存器），**性价比最高**。

### 4.8 超轻量化网络自设计（高阶）

**方法**：
- 结构化剪枝 + 通道裁剪 + INT8 量化；
- 可考虑 BNN/TNN（二值/三值）——用 XNOR+popcount 或符号位运算替代乘法器，极大降低 DSP 需求；
- 输出网络结构图、参数量表；与标准网络做 PSNR/SSIM 与延迟对比；
- **<500KB 约束**：注意仍大于片上 327KB BRAM，需流式或进一步压缩（稀疏编码/权值共享）。

### 4.9 创意交互（高阶）

| 方向 | 硬件/接口 | 实现要点 |
|---|---|---|
| 语音控制 | SPI 语音模块 | RISC-V 发指令切换风格 |
| 手势识别 | 复用摄像头 + 简单运动/形状检测 | 帧差/连通域，可由 FPGA 加速 |
| 实时推流到手机 | WiFi 模块（UART/SPI）+ GE | 压缩帧经 WiFi/以太网推送 |
| 短视频展示 | 录制 | 附加材料 |

## 五、分级资源占用与性能预算

以下为**估算值**，以实际综合报告为准。工程上线前建议先做一次"资源探针综合"（只放 IP + 骨架）确认可用余量。

| 等级 | LE 占用（估） | DSP | BRAM | DDR 带宽 | 目标性能 |
|---|---|---|---|---|---|
| L0 | <2K | 0 | 极少 | – | 彩条 |
| L1 | 30~45K（含 CSI IP、DDR IP） | 少量 | ~30~50% | 帧流 <60MB/s | 640×480 采集 |
| L2 | L1 + 10~25K | 32~96 | 行缓存+权重 | +权重流 | 单帧/低帧率 |
| L3 | L1+L2 + SoC 10~15K | 64~128 | 高 | 帧流+特征 | 可见效果 |
| L4 | 同 L3 | 同 L3 | 同 L3 | 同 L3 | 640×480 ≥15fps |
| L5b | 更高并行度/更强流水 | 130~160 | 接近上限 | 优化访存 | 720p@30（需大幅优化） |

> **提醒**：CSI-2 RX + DDR3 控制器 + Sapphire SoC 三个大件已占据可观 LE/BRAM，务必给 CNN 加速器预留 DSP 与 BRAM。

## 六、推荐系统架构与数据流

```
                ┌─────────────── Ti60F225I3 ───────────────┐
 SC431HAI       │                                            │
 (4-lane MIPI)──┼─► MIPI D-PHY RX ─► CSI-2 RX ─► Debayer ─► Resize ─┐
                │                                              │   │
                │                        ┌── Ping-Pong DDR3 ◄──┘   │
                │                        │   (帧缓存 + 权重)         │
                │                        ▼                          │
                │   RISC-V Sapphire ──► CNN 加速器 ◄── 权重流式读取   │
                │   (I2C/调度/UI)         │                          │
                │                        ▼                          │
                │   OSD 叠加/分屏 ◄──── 结果帧 ◄──────────────────┘
                │        │
                │        ▼
                └─► HDMI TX (TMDS) ─► 显示器
```

数据流要点：
1. 采集 → 预处理 → 写 DDR（缓冲 A）；
2. CNN 从 DDR 读图块 + 权重，行流式处理后写结果帧（缓冲 B）；
3. 显示从 DDR 读原图/结果帧，OSD 分屏输出；
4. RISC-V 负责配置、调度、模式切换。

## 八、关键风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| 片上 RAM 仅 327KB | 网络权重放不下 | 权重流式 + 量化 + 剪枝 |
| DSP 仅 160 | 720p@30 算力不足 | 降通道、BNN/TNN、行流式、抽帧 |
| Instance Norm 难离线折叠 | 运行时开销大 | 硬件近似 / 用 BN 替代 / 简化统计 |
| MIPI 电平/跳线 | 采集不通 | J2/J3 选 1.2V；核对 SC431HAI 电平 |
| DDR 中间结果访存爆炸 | 帧率上不去 | 层间融合 + 行流水线，避免整帧往返 |
| 多风格切换丢帧 | 高阶扣分 | 帧边界切换 + 权重双缓冲预取 |
| 时序不收敛 | 频率上不去 | 流水线打拍、合理约束、避免长组合路径 |
| 资源超限 | 无法布局布线 | 早期资源探针综合，留 15~20% 余量 |
